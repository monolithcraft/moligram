# Архитектура

Moligram — десктопный клиент Telegram. Первая платформа — Linux, архитектура
с самого начала не привязана к ней: всё платформенное изолировано в одном модуле.

## Стек

| Слой | Технология | Почему |
| --- | --- | --- |
| Язык | C++23 | скорость, прямой доступ к TDLib и Qt без прослоек |
| Интерфейс | Qt 6 Quick (QML) | отрисовка на GPU, любой дизайн, анимации, Wayland |
| Протокол | TDLib (нативный C++ API) | официальная библиотека Telegram: протокол, шифрование, синхронизация |
| Локальная база | SQLite + SQLCipher | шифрованное хранилище для наших данных (история, фильтры) |
| Секреты | libsecret (Secret Service) | ключи шифрования в системном хранилище, а не в файлах |
| Сборка | CMake + Ninja, пресеты | стандарт для C++ и Qt |

## Структура репозитория

```
moligram/
├── CMakeLists.txt
├── CMakePresets.json        debug, release, asan
├── cmake/                   предупреждения компилятора, санитайзеры, поиск зависимостей
├── src/
│   ├── app/                 точка входа, сборка зависимостей, жизненный цикл
│   ├── core/                общие типы без Qt Quick: Result, ошибки, логирование
│   ├── telegram/            клиент TDLib, очередь запросов, разбор обновлений
│   ├── storage/             зашифрованная база, настройки, ключи
│   ├── features/            логика функций без UI
│   │   ├── ghost/
│   │   ├── history/
│   │   ├── streamer/
│   │   └── filters/
│   ├── models/              модели данных для QML: чаты, сообщения, участники
│   ├── platform/            Linux: порталы, трей, хранилище секретов, уведомления
│   └── ui/                  QML
│       ├── design/          модуль Moligram.Design: токены, тема, типографика, движение
│       ├── controls/        модуль Moligram.Controls: кнопки, поля, аватары, меню
│       └── screens/         модуль Moligram.Screens: вход, список чатов, чат, настройки
├── resources/               иконки, шрифты, брендинг
├── tests/                   юнит- и интеграционные тесты по модулям
├── packaging/               Flatpak, AUR, AppImage
├── third_party/tdlib/       TDLib как git submodule с зафиксированной версией
└── docs/
```

У каждого модуля в `src/` — короткий `README.md`: за что отвечает
и от чего зависит.

## Зависимости между модулями

| Модуль | Зависит от |
| --- | --- |
| `app` | `ui`, `models`, `features`, `platform` |
| `ui` | только QML-модули друг друга; данные получает из `models` |
| `models` | `features`, `telegram` |
| `features` | `telegram`, `storage` |
| `telegram` | `core` |
| `storage` | `core` |
| `platform` | `core` |
| `core` | ничего, кроме Qt Core |

- Зависимости идут только вниз. `features` не знает про QML, `telegram`
  не знает про функции Moligram.
- Каждый модуль — отдельная CMake-цель, нарушение направления ломает сборку.
- Типы TDLib (`td_api::*`) не выходят за пределы `telegram`. Наружу отдаются
  наши доменные структуры. Это изолирует проект от изменений в TDLib.

## Потоки

- **Главный поток** — только UI и модели. Никаких блокирующих вызовов.
- **Поток TDLib** — цикл `receive()`; ответы и обновления передаются
  в главный поток очередью событий Qt, пачками, чтобы не дёргать UI
  на каждое обновление.
- **Пул фоновых задач** — декодирование изображений, превью, работа с базой.

## Ghost Mode и политика запросов

Все запросы к Telegram, которые оставляют «следы», проходят через одну точку:

```
UI ──► features ──► RequestGate ──► telegram ──► TDLib
                        │
                   GhostPolicy
```

`RequestGate` решает, отправить, задержать или отменить запрос: `viewMessages`,
`openStory`, `sendChatAction`, опция `online`. Политика — чистая функция
от настроек и контекста (аккаунт, чат, время), поэтому она полностью
покрывается тестами. В остальном коде проверок на Ghost Mode нет.

## Message History

- TDLib сообщает об удалении (`updateDeleteMessages`) и правках
  (`updateMessageContent`, `updateMessageEdited`).
- Перед применением изменения `features/history` снимает копию сообщения
  из модели и пишет её в зашифрованную базу.
- Медиа удалённых сообщений сохраняется в отдельный каталог, если
  было загружено, или докачивается, пока файл ещё доступен.
- При показе чата удалённые сообщения встраиваются в ленту по дате
  и ID, а не по границам страниц загрузки.

## Безопасность

- База TDLib шифруется ключом `database_encryption_key`, база Moligram —
  ключом SQLCipher. Оба ключа случайные, хранятся в Secret Service.
- Каталог данных создаётся с правами `0700`.
- Секреты, токены и тексты сообщений не пишутся в логи.
- Внешний ввод (deep link, импорт фильтров, файлы) проверяется в одном месте.
- В отладочных сборках — AddressSanitizer и UBSan, в CI — clang-tidy
  и проверка зависимостей.

## Производительность

- Списки только через виртуализированные `ListView` и модели на C++
  с ролями; делегаты лёгкие, без вложенных загрузчиков.
- Изображения декодируются асинхронно, с кэшем по размеру отображения.
- Обновления от TDLib объединяются перед передачей в модели.
- Тяжёлые эффекты (размытие, зерно) рисуются на статичных слоях и кэшируются.
- Время запуска и плавность прокрутки замеряются в CI.

## Сборка

Зависимости (Arch Linux):

```bash
sudo pacman -S --needed cmake ninja gperf qt6-base qt6-declarative qt6-multimedia qt6-svg qt6-shadertools sqlcipher libsecret openssl zlib
```

TDLib подключён как подмодуль и собирается один раз в `.deps/`:

```bash
git submodule update --init
```

```bash
./scripts/build-tdlib.sh
```

Сборка приложения:

```bash
cmake --preset debug
```

```bash
cmake --build --preset debug
```

Пресеты: `debug` (предупреждения как ошибки), `release` (LTO), `asan` (AddressSanitizer и UBSan).
