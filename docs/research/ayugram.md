# Разбор: AyuGram

Источник: <https://github.com/AyuGram>. Только анализ идей, код не переносим.

## Что это

Набор модифицированных клиентов Telegram с упором на приватность
и «возможности за рамками ToS».

| Репозиторий | Основа | Язык | Состояние |
| --- | --- | --- | --- |
| AyuGramDesktop | форк Telegram Desktop | C++ / Qt | активен |
| AyuGram4A | форк exteraGram (форк Telegram Android) | Java | давно не обновлялся |
| AyuGramX | форк moeGramX (Telegram X) | Java | заброшен |
| lib_ui, lib_tl, codegen | форки библиотек tdesktop | C++ | патчи под клиент |

Лицензия наследуется от Telegram Desktop — GPL-3.0.

## Как устроено

Свой код собран в отдельной папке (`SourceFiles/ayu`): настройки, своя база
SQLite (через sqlite_orm), фичи, свои UI-компоненты. Но для подключения
к клиенту правятся **около 320 файлов** исходного tdesktop: проверки вида
«если включён режим невидимки — не отправлять запрос» вставлены прямо
в сетевые вызовы (`api_views`, `api_send_progress`, `api_polls` и т.д.).

Плюсы: быстро получить полноценный клиент со всеми функциями Telegram.

Минусы:
- каждое обновление upstream превращается в разрешение конфликтов;
- логика фич размазана по чужому коду, её трудно тестировать и читать;
- настройки — один большой синглтон на ~120 полей.

Вывод для нас: если строим на форке, нужен **один слой перехвата** запросов
(политика «что можно отправлять»), а не проверки в каждом вызове.

## Функции

### Приватность
- **Невидимка** — по отдельности: не отправлять прочтение сообщений,
  прочтение историй, статус «в сети», «печатает…»; принудительный оффлайн
  после действия. Настраивается для каждого аккаунта.
- **Прочитать при ответе** — отмечать прочитанным только когда пользователь
  сам что-то сделал в чате.
- **Отправка через отложенные сообщения** — чтобы не появляться в сети
  (задержка зависит от размера файла).
- **Предупреждение перед открытием истории.**
- **Подглядеть «был в сети»** — через временное исключение в настройках
  приватности или через второй аккаунт.

### История сообщений
- Сохранение удалённых и всех версий отредактированных сообщений в отдельной
  базе, независимой от кэша Telegram.
- Попытка скачать медиа до того, как оно удалится с сервера.
- Отметки «удалено» / «изменено», полупрозрачные удалённые сообщения,
  отдельный экран просмотра удалённого с поиском.
- Известная проблема: удалённые сообщения на стыке страниц подгрузки
  не показываются.

### Фильтры
- Скрытие сообщений по регулярным выражениям: глобально, по чату,
  с исключениями. Фильтр по типу сообщения и по кнопкам.
- Скрытие сообщений заблокированных пользователей.
- Импорт наборов фильтров по deep link с белым списком доменов.

### Внешний вид
- Свой шрифт, моноширинный шрифт, радиус пузырей, хвостики, скругление
  аватаров, иконка приложения на выбор.
- Тонкая настройка: кнопки в поле ввода, пункты бокового меню
  и контекстного меню.
- Скриншот сообщения в виде картинки (message shot) с темой.
- Упрощённые цитаты и ответы.

### Прочее
- Режим стримера (скрыть окно от захвата экрана, платформенная реализация).
- Встроенный переводчик (Google, Yandex).
- Локальный Premium (только клиентские функции).
- ID пользователей в профиле, открытие профиля по ID.
- Подтверждения перед отправкой стикера / GIF / голосового.
- Отключение историй, рекламы, похожих каналов, задержки уведомлений.
- Пересылка без «переслано от», синхронизация между устройствами.

## Что берём как идеи

- Гибкая невидимка по аккаунтам — да, но через единую политику исходящих
  запросов.
- Локальная история удалённого и изменённого — да, в отдельной
  зашифрованной базе, без проблемы «стыков страниц».
- Фильтры — да, но с понятным конструктором вместо голых регулярок.
- Режим стримера, скриншот сообщения, подтверждения отправки — да.
- Огромный экран с сотней переключателей — нет. Настройки группируем
  и даём пресеты.
