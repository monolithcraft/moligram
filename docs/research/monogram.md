# Разбор: Monogram

Источник: <https://github.com/monogram-android>. Только анализ идей, код не переносим.

## Что это

Нативный клиент Telegram для Android 7.0+, написанный **с нуля**, а не форком
официального приложения. Лицензия GPL-3.0.

| Репозиторий | Что внутри |
| --- | --- |
| monogram | Android-приложение: Kotlin, Jetpack Compose, Material 3 |
| mono-rs | собственная реализация MTProto на Rust |
| rlottie, emojies | анимации стикеров и наборы эмодзи |

## Архитектура приложения

Многомодульный Gradle-проект (~800 файлов Kotlin):

| Модуль | Ответственность |
| --- | --- |
| `app` | точка входа, DI, корневая навигация, пуши |
| `core/common, models, ui, database, markup` | общие модели, Room, UI-компоненты, тема |
| `feature/auth, chats, dialog, folders, profile, settings` | экраны |
| `network/bridge` | граница между Kotlin и Rust: доменные API, DTO, маппинг ошибок |
| `network/http` | загрузка медиа по HTTP, кэш, очередь |
| `native/mtproto-rs, markup-rs` | Rust-код, экспорт в Kotlin через UniFFI |

Правила, которые они соблюдают:
- зависимости идут строго `app → feature → core/network`; фичи не зависят
  друг от друга и не видят сгенерированные типы UniFFI;
- навигация — Decompose, состояние — MVIKotlin (Store / Executor / Reducer);
- composable-функции получают неизменяемое состояние и колбэки;
- ошибки протокола превращаются в доменный `TelegramError` на границе,
  UI не знает имён ошибок TL;
- версии зависимостей в одном каталоге (`libs.versions.toml`).

## mono-rs (MTProto на Rust)

Рабочее пространство из ~19 крейтов: `codec`, `crypto`, `transport`, `socket`,
`session`, `storage`, `updates`, `media`, `messages`, `runtime`, `client`,
собственный парсер и генератор TL-схемы.

Сильные стороны:
- файл сессии зашифрован AES-256-GCM, повреждённый файл не затирает рабочий;
- временные ключи (PFS) для дополнительных соединений;
- параллельная загрузка медиа с докачкой, поддержка CDN с проверкой хешей;
- библиотека сама упорядочивает обновления и закрывает пропуски
  (`pts` / `qts` / `seq`), выдаёт пачки, переживающие падение;
- SOCKS5, HTTP-прокси, MTProxy;
- `unsafe_code = "forbid"`, строгий clippy.

Ключ шифрования сессии хранится через Android Keystore.

## Минусы и риски

- Проект молодой, многие функции Telegram ещё не реализованы.
- Своя реализация протокола — огромный объём работы и постоянная гонка
  за новыми слоями API.
- Только Android.

## Что берём как идеи

- Модульная структура с жёсткими границами и описанием каждого модуля.
- Протокол и криптография в Rust, UI нативный — хорошее сочетание
  скорости и безопасности.
- Шифрование сессии ключом из системного хранилища.
- Единая точка маппинга ошибок.
- Позиция «без NFT и крипты» — близка нам, стоит обсудить.
